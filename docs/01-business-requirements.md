# 要求仕様書 (Business Requirements Document)

本ドキュメントは、ブログWebアプリケーションバックエンド（nextjs-echo-back-blog-app）の要求仕様を定義する。既存のソースコードからリバースエンジニアリングにより作成されたものである。

---

## 1. プロジェクト背景

個人開発者として、Zenn・Qiita等の技術記事プラットフォームに散在する自身の記事や、GitHubリポジトリ上のMarkdownコンテンツを一元管理するための技術ブログプラットフォームを構築する。

従来、複数のプラットフォームに分散していた技術記事を、自前のブログサイトに集約し、GitHubのMarkdownファイルを参照する形でコンテンツを表示する仕組みを実現する。これにより、記事管理の効率化と独自ブランドの構築を目指す。

---

## 2. プロジェクト目的・ゴール

| # | 目的 | 詳細 |
|---|------|------|
| G-001 | コンテンツ集約 | Zenn・Qiita・GitHub上の技術記事を一箇所に集約し、読者に統一的な閲覧体験を提供する |
| G-002 | コスト効率の最大化 | Cloud Run無料枠およびSupabase無料枠を活用し、ランニングコストを最小限に抑える |
| G-003 | GitHub連携による効率的な記事管理 | ブログ記事の本文をGitHub上のMarkdownファイルとして管理し、記事の作成・編集をGitHubワークフローに統合する |
| G-004 | 読者エンゲージメント | いいね機能やコメント機能を通じて、読者との双方向コミュニケーションを実現する |
| G-005 | 拡張性の確保 | クリーンアーキテクチャに基づく設計により、将来的な機能追加を容易にする |

---

## 3. ステークホルダー

### 3.1 ブログオーナー（個人開発者）

- ブログ記事のCRUD操作（作成・取得・更新・削除）を行う
- 認証されたユーザーとしてログインし、管理機能を利用する
- ユーザープロフィール（名前・メールアドレス・パスワード）の管理を行う

### 3.2 ブログ読者（訪問者）

- ブログ記事の一覧閲覧・詳細閲覧を行う
- カテゴリ・タグによる記事のフィルタリング
- 人気記事ランキングの閲覧
- いいね機能の利用（匿名、訪問者IDベース）
- ゲストコメントの投稿

---

## 4. スコープ

### 4.1 対象範囲

| 項目 | 説明 |
|------|------|
| バックエンドAPI | Go + Echo フレームワークによるREST APIの提供 |
| 認証機能 | JWT（JSON Web Token）によるユーザー認証 |
| データ永続化 | Supabase（PostgreSQL）によるデータ管理 |
| インフラストラクチャ | Google Cloud Run上へのデプロイ |
| IaC | Terraformによるインフラ構成管理 |
| CI/CD | GitHub Actionsによる自動デプロイ |

### 4.2 対象外

| 項目 | 説明 |
|------|------|
| フロントエンド | 別リポジトリで管理（Next.js + TypeScript + Hono） |
| 記事本文の保存 | 記事本文はGitHub上のMarkdownとして管理し、本システムはGitHub URLの参照のみ保持 |
| メール通知 | コメント通知等のメール機能は含まない |
| ファイルアップロード | 画像等のファイルアップロード機能は含まない |
| 全文検索 | ブログ記事の全文検索機能は含まない |

## 5. システム構成

### 5.1 技術スタック

| レイヤー | 技術 | バージョン |
|----------|------|------------|
| 言語 | Go | 1.20 |
| Webフレームワーク | Echo | v4.12.0 |
| データベース | Supabase (PostgreSQL) | pgx v4.18.3 |
| 認証 | JWT | golang-jwt v3.2.2 |
| インフラ | Google Cloud Run | - |
| IaC | Terraform | - |
| CI/CD | GitHub Actions | - |

### 5.2 アーキテクチャ

クリーンアーキテクチャに基づくレイヤー構成を採用する。

```
Handler（プレゼンテーション層）
  ↓ インターフェース経由でDI
Service（ビジネスロジック層）
  ↓ インターフェース経由でDI
Repository（データアクセス層）
  ↓
Supabase (PostgreSQL)
```

各レイヤー間はインターフェースによる依存性注入（DI）で疎結合を実現し、テスタビリティを確保する。

### 5.3 通信方式

- フロントエンド-バックエンド間：REST API（JSON形式）
- 認証情報の伝達：HTTP-Only Cookie（JWTトークン）
- CORS：Credentials付きのクロスオリジンリクエストに対応

## 6. 制約条件

### 6.1 コスト制約

| 項目 | 制約 | 詳細 |
|------|------|------|
| コンピューティング | Cloud Run無料枠 | 月間180,000 vCPU秒、360,000 GiB秒のメモリを上限とする |
| データベース | Supabase無料枠 | 500MBのデータベースストレージ、50,000行の上限を目安とする |
| ネットワーク | 無料枠内 | リージョン内の通信を最大限活用する |

### 6.2 技術制約

| 項目 | 制約 |
|------|------|
| パスワード管理 | 現行実装ではパスワードは平文でDBに保存されている（将来的にハッシュ化が推奨される） |
| セッション管理 | JWTトークンの有効期限は1時間固定 |
| 訪問者ID | visit-id-tokenの有効期限は1時間固定 |
| コネクションプール | 最大10接続、アイドルタイムアウト30秒 |

### 6.3 運用制約

| 項目 | 制約 |
|------|------|
| ユーザー数 | 単一ユーザー（ブログオーナー）の認証のみ対応 |
| スケーラビリティ | 個人ブログ規模のトラフィックを想定 |
| 可用性 | Cloud Runのマネージドサービスに準拠 |

## 7. 環境変数

| 変数名 | 用途 | 必須 |
|--------|------|------|
| PORT | サーバーリスンポート（デフォルト: 8080） | No |
| JWT_SECRET_KEY | JWTトークンの署名に使用する秘密鍵 | Yes |
| ENV | 実行環境（"production" でHTTPS Cookie有効化） | No |
| ALLOWED_ORIGINS | CORS許可オリジン（カンマ区切り） | Yes |
| SUPABASE_URL | Supabaseデータベース接続URL | Yes |

## 8. データモデル概要

### 8.1 blog_users（ブログユーザー）

ブログオーナーの認証情報およびプロフィール情報を管理する。

| カラム | 型 | 説明 |
|--------|------|------|
| id | UUID | 主キー |
| name | string | ユーザー名 |
| email | string | メールアドレス |
| password | string | パスワード |
| created_at | timestamp | 作成日時 |
| updated_at | timestamp | 更新日時 |

### 8.2 blogs（ブログ記事）

ブログ記事のメタデータとGitHub URL参照を管理する。

| カラム | 型 | 説明 |
|--------|------|------|
| id | UUID | 主キー |
| blog_user_id | UUID | 作成者ユーザーID（外部キー） |
| title | string | 記事タイトル |
| description | string | 記事説明 |
| github_url | string | GitHub上のMarkdownファイルURL |
| category | string | カテゴリ |
| tags | string | タグ（カンマ区切り） |
| likes | int8 | いいね数（集計値） |
| comment_cnt | int8 | コメント数（集計値） |
| created_at | timestamp | 作成日時 |
| updated_at | timestamp | 更新日時 |

### 8.3 blog_likes（いいね）

訪問者によるいいね情報を管理する。

| カラム | 型 | 説明 |
|--------|------|------|
| id | UUID | 主キー |
| blog_id | UUID | ブログ記事ID（外部キー） |
| visit_id | string | 訪問者ID |
| created_at | timestamp | 作成日時 |
| updated_at | timestamp | 更新日時 |

### 8.4 blog_comments（コメント）

ゲストユーザーによるコメント情報を管理する。

| カラム | 型 | 説明 |
|--------|------|------|
| id | UUID | 主キー |
| blog_id | UUID | ブログ記事ID（外部キー） |
| guest_user | string | ゲストユーザー名 |
| comment | string | コメント本文 |
| created_at | timestamp | 作成日時 |
